# Google Play 데이터 보안 작성 기준

이 문서는 현재 코드 흐름을 기준으로 한 Play Console 답변 초안이다. 운영 서버의 실제 보존 기간, 접근 통제, 로그 정책과 일치하는지 출시 책임자가 최종 확인해야 한다.

## 공통 답변 초안

- 사용자 데이터를 수집하거나 공유하는가: 수집함
- 전송 중 암호화: 예(HTTPS/TLS)
- 계정 삭제 요청 방법 제공: 예. 앱 설정의 `계정 삭제`와 웹 `/delete-account`
- 독립 보안 검토: 완료된 검토가 있을 때만 예로 답변

## 데이터 유형별 신고

| Play 데이터 유형 | 사용 시점 | 목적 | 필수 여부 | 처리·보존 |
|---|---|---|---|---|
| 이름, 이메일 주소, 사용자 ID, 프로필 사진 | Google 로그인 | 계정 관리, 앱 기능 | 앱 사용에 필수 | Google 인증 응답과 로컬 세션. 계정 삭제 시 앱 연결 해제, 기기 데이터 삭제, 서버 저장 장소 삭제 |
| 주소·장소 이름(최근 선택한 장소) | 사용자가 목적지를 선택할 때 | 앱 기능(기기 간 최근 장소 재사용) | 선택 | 로그인 계정의 Google 사용자 ID를 키로 Supabase `saved_places`에 계정당 최근 24건 저장. 계정 삭제 시 함께 삭제 |
| 대략적·정확한 위치 | 홈 날씨, 출발지/경로 계산, 사용자가 켠 이동 안내 | 앱 기능 | 해당 기능에 선택 | 날씨 확인 시 약 1km 수준으로 반올림한 좌표를 TimeAgent 날씨 중계 서버에 전송하고 기상청 우선·Open-Meteo 대체로 처리. 경로 공급자 프록시에도 전송될 수 있음. 백그라운드 이동 세션 기록은 기기에 임시 저장하고 중지·도착 시 삭제 |
| 캘린더 일정 제목·시간·장소 | 사용자가 기기 캘린더 권한을 허용하고 가져올 때 | 앱 기능 | 선택 | 기기에서 읽어 사용자가 고른 일정 초안에 반영. 캘린더 원본은 수정·삭제하지 않음 |
| 음성 또는 소리 녹음 | 음성 일정 만들기 | 앱 기능 | 선택 | 사용자 요청 시 AI 프록시로 전송해 일정 초안을 생성 |
| 기타 사용자 생성 콘텐츠 | 일정 제목·장소·준비 항목·음성 일정 초안 | 앱 기능, 개인화 | 핵심 일정 기능에는 필요 | 기본적으로 기기 로컬 저장. AI 기능 사용 시 관련 초안이 처리 서버로 전송될 수 있음 |
| 앱 활동·진단 | 완료 기록, 계획 적용, 오류 상태 | 앱 기능, 개인화, 안정성 | 기능별 선택 | 현재 코드의 로컬 저장 및 운영 서버 로그 정책에 맞춰 최종 신고. Plus 미리보기를 닫을 때 완료 횟수·정시 도착률 등 집계값과 사용자가 고른 유형을 계정 단위 한 행으로 전송(`POST /v1/pilot-summary`). 일정명·장소·좌표·음성·기기 식별자·이벤트 시각은 포함하지 않음 |

## 공유 여부 판단

기상청, Open-Meteo, NAVER/TMAP, Google, Gemini 및 Supabase가 사용자 요청을 처리하는 서비스 제공자 역할로만 데이터를 처리하고 광고·독자 목적에 사용하지 않는 계약이라면 Play 정의상 `공유` 예외가 적용될 수 있다. 계약과 실제 운영 로그를 확인하기 전에는 임의로 `공유하지 않음`을 확정하지 않는다.

## 출시 전 운영 확인

1. Supabase 함수 로그에 위치·음성·일정 본문이 남는지와 보존 기간을 확인한다.
2. AI·지도 공급자의 데이터 사용 및 보존 조건을 개인정보처리방침에 반영한다.
3. 계정 삭제는 Google 접근 철회, 기기 로컬 데이터 삭제, 서버 저장 장소 삭제(`DELETE /v1/saved-places`), 검증 집계 삭제(`DELETE /v1/pilot-summary`)를 수행한다. 서버 삭제가 하나라도 실패하면 계정 삭제를 중단하므로 데이터가 남은 채 계정만 사라지지 않는다.
4. 개인정보처리방침 공개 URL과 앱 내 문안이 동일한지 확인한다.
