# Ralph Loop

Ralph Loop는 한 번의 큰 프롬프트로 모든 기능을 만들지 않고, 가장 작은 사용자 가치 단위를 선택해 구현과 검증을 반복하는 작업 방식이다.

## 매 반복의 입력

- `docs/PRODUCT.md`의 수용 기준
- `docs/DESIGN_SYSTEM.md`의 화면/접근성 규칙
- `docs/EXECUTION_PLAN.md`의 가장 높은 우선순위 미완료 항목
- 현재 코드와 직전 `npm run verify` 결과

## 반복 절차

1. **Observe**: 현재 동작과 실패를 재현한다.
2. **Select**: 한 번에 하나의 사용자 결과만 선택한다.
3. **Specify**: 정상, 지연, 오류 상태를 Given/When/Then으로 적는다.
4. **Implement**: 계산 로직 → 상태 → UI 순서로 최소 변경한다.
5. **Verify**: 관련 테스트 후 `npm run verify`, 대상 화면 크기 확인을 실행한다.
6. **Reflect**: 구현이 요구사항을 충족했는지, 새 부채가 생겼는지 기록한다.
7. **Commit-ready**: 변경 파일, 테스트 증거, 남은 위험을 요약하고 다음 항목으로 이동한다.

## 에이전트용 반복 프롬프트

```text
ON:TIME 저장소에서 docs/PRODUCT.md, docs/DESIGN_SYSTEM.md,
docs/HARNESS.md, docs/EXECUTION_PLAN.md를 읽어라.

EXECUTION_PLAN에서 우선순위가 가장 높은 미완료 항목 하나만 선택하라.
수용 기준을 Given/When/Then으로 확인하고 필요한 테스트를 먼저 추가하라.
구현은 기존 디자인 토큰과 도메인 경계를 지켜 최소 범위로 수행하라.
npm run verify를 통과시키고 관련 화면을 360x800, 390x844,
430x932에서 확인하라.

검증이 끝난 경우에만 해당 체크박스를 완료로 바꾸고, 실행한 명령과
남은 위험을 항목 아래에 짧게 기록하라. 실패를 숨기거나 테스트를
완화하지 말라. 한 항목을 끝내면 멈춰 결과를 보고하라.
```

## 루프 중단 조건

- 필요한 API 키, 공급자, 과금 정책 등 제품 결정이 없으면 구현 방향이 크게 달라지는 경우
- 데이터 삭제, 배포, 외부 메시지 전송처럼 새 권한이 필요한 경우
- 같은 환경 실패가 세 번 재현되고 안전한 우회가 없는 경우
- 선택 항목의 수용 기준이 서로 충돌하는 경우

중단 시 추측으로 범위를 넓히지 않고 재현 결과, 시도한 방법, 필요한 결정을 보고한다.

## 완료의 정의

코드 작성만으로 완료하지 않는다. 수용 기준 충족, 자동 검증 통과, 대상 크기 시각 확인, 접근성 레이블과 상태 문구 확인, 실행 계획 업데이트까지 끝나야 완료다.
