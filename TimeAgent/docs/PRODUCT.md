# 제품 요구사항

## 제품 정의

TimeAgent는 계획표나 약속 알람이 아니라, 계획이 실제 행동으로 이어질 때까지 시간을 운영하는 AI 에이전트다. 일정과 할 일을 입력하면 실행 가능한 첫 행동, 준비, 전환, 이동, 도착을 연결하고 실제 진행이 달라질 때 남은 하루를 다시 계산한다.

브랜드 포지셔닝은 다음 문장으로 통일한다.

> ADHD 사용자가 계획을 잘 세우도록 돕는 앱이 아니라, 계획이 실제 행동으로 이어질 때까지 시간을 대신 운영하는 AI 에이전트.

TimeAgent는 ADHD 진단·치료·의료적 판단을 제공하거나 대체하지 않는다. 사용자가 실행과 시간 관리를 쉽게 하도록 돕는 생활 지원 도구이며, 필요한 경우 전문적인 평가와 치료를 별도로 안내한다.

## 핵심 사용자 루프

제품은 할 일을 기록하는 데서 끝나지 않고 다음 루프를 끊김 없이 지원한다.

`기억하기 → 시작하기 → 시간 인식하기 → 전환하기 → 실패 후 복구하기`

각 단계의 제품 책임은 다음과 같다.

| 단계 | 사용자 질문 | TimeAgent의 책임 |
|---|---|---|
| 기억하기 | 무엇을 놓치고 있지? | 음성·자연어·캘린더로 입력 비용을 줄이고 맥락을 보존한다. |
| 시작하기 | 지금 뭘 해야 하지? | 긴 목록 대신 지금 할 행동 하나를 보여주고 5분 시작 단위로 줄인다. |
| 시간 인식하기 | 시간이 얼마나 남았지? | 숫자와 함께 줄어드는 바·원·타임라인으로 시간 흐름을 외부화한다. |
| 전환하기 | 언제 멈추고 옮겨야 하지? | 예고→마무리→종료→다음 첫 행동을 단계적으로 안내한다. |
| 복구하기 | 계획이 틀어졌는데 이제 뭘 하지? | 비난 없이 남은 시간 기준 대안을 계산하고 적용 여부를 사용자가 결정하게 한다. |

## 제품 원칙

- 개인차 우선: 시간 추정·재현의 어려움을 모든 ADHD 사용자에게 전제하지 않는다. 기능 강도와 개입 빈도는 사용자가 조정할 수 있어야 한다.
- 한 번에 하나: 기본 홈과 진행 화면은 `지금–다음–나중` 구조를 사용하고, 가장 중요한 다음 행동 하나만 시각적으로 우선한다.
- 시작 마찰 최소화: 큰 작업은 동사로 시작하는 2~5분 행동으로 분해하고 `5분만 시작`을 제공한다.
- 시간 외부화: 카운트다운 숫자만 두지 않고 전체 대비 남은 시간을 시각적으로 표현한다. 색상만으로 상태를 전달하지 않는다.
- 단계적 전환: 기본 전환 개입은 15분 전 예고, 5분 전 마무리, 종료 시 전환 행동이다. 일정 특성과 사용자 설정에 따라 조정한다.
- 무시해도 사라지지 않음: 알림을 닫거나 놓친 경우 `5분 뒤 시작`·`오늘 재배치`·`취소` 중 다음 결정을 요청하고 관련 일정을 재계산한다.
- 수치심 없는 복구: 연속 기록 상실이나 실패를 강조하지 않고, 현재 가능한 다음 행동과 복구안을 먼저 제시한다.
- 설명 가능한 자동화: AI 변경에는 이유와 변경 전후를 표시하고 `적용`·`수정`·`유지`·`취소`를 항상 제공한다.
- 학습은 제안으로: 예상·실제 소요시간을 학습하되 다음 일정의 시간과 버퍼는 자동 확정하지 않고 근거가 있는 추천값으로 제시한다.

## MVP 가설

- 정상적인 일정의 80~90%는 음성 한 번과 확인 한 번으로 등록할 수 있다.
- “지금 무엇을 해야 하는가”가 3초 안에 이해된다.
- 큰 작업을 5분 이내의 첫 행동으로 줄이면 실제 시작률이 높아진다.
- 준비·이동·전환을 역산한 개입은 약속 시각 알림보다 제때 전환할 가능성을 높인다.
- 지연 시 남은 하루 기준 최대 3개의 복구안을 비교하면 다음 행동을 빠르게 선택할 수 있다.
- 실제 소요 시간을 다음 계획에 반영하면 정시 도착률이 높아진다.

## 핵심 사용자

- 준비 시작 시점을 자주 놓치는 대학생
- 연속 일정과 이동 시간을 함께 관리해야 하는 직장인
- 준비 루틴이 길고 일정마다 달라지는 사용자

## MVP 범위

### 포함

- 음성·자연어 중심 일정·할 일 입력과 추출값 확인·부분 수정
- 큰 작업을 실행 가능한 다음 행동으로 자동 분해하고 `5분만 시작`
- `지금–다음–나중`과 한 번에 하나의 현재 행동
- AI 준비 계획과 세로 타임라인
- 준비·이동·주차·전환 시간을 포함한 역산 알림
- 독립 이동수단 `도보`와 버스·지하철 등 복합 경로의 출발지·목적지 도보 구간
- 약속 날짜·시각의 운행시간표를 반영한 대중교통 경로와 출발 시각 계산
- 출발이 가까워지면 선택 경로의 첫 탑승 구간에 한해 제공 가능한 지역의 실시간 도착정보 반영
- 남은 시간을 숫자와 감소형 시각 요소로 보여주는 실시간 진행
- 15분 예고·5분 마무리·종료 전환의 단계적 개입
- 무시한 알림의 `5분 뒤 시작`·`오늘 재배치`·`취소` 결정
- 지연 시 남은 하루 재계획, 변경 전후·이유·적용 여부 확인
- 플랜 B: 다음 버스, 지하철, 택시
- 예상·실제 소요 시간 비교와 개인화 추천값
- 기본 위치, 루틴, 이동 우선순위, 알림, 권한 설정
- 기기에 연결된 Google·Apple/iCloud·Android 캘린더 일정 조회와 명시적 가져오기
- 앱 실행 시 Google 계정 로그인과 로그인 상태 복원
- 선택 안 함·여성·남성 중 사용자가 고른 기준으로 새 일정의 기본 준비 항목 추천
- 현재 위치의 날씨·기온·체감온도·최고/최저·강수확률과 일정 준비 행동 안내

### 후순위

- 친구 공유, 다중 사용자 약속 조정
- 고급 습관 리포트와 구독
- 완전한 캘린더 대체 기능
- Apple·Kakao 등 추가 소셜 로그인

## 핵심 흐름과 수용 기준

### 첫 일정 생성

Google 로그인 → 온보딩 → 권한 설명 → 홈 빈 상태 → 음성으로 일정 말하기 → 추출값·지도 확인 → 한 번 탭해 확정.

- 필수 입력과 추천값을 구분한다.
- 입력은 자동 저장되며 장소 검색 실패 시 직접 입력할 수 있다.
- Google 로그인을 완료해야 앱 내부 화면으로 이동할 수 있다.

### 작업 시작

할 일 말하기 → AI 행동 분해 → 첫 행동 확인 → `5분만 시작` → 현재 행동 한 개 표시.

- `보고서 작성` 같은 결과형 표현을 `문서 열기`처럼 관찰 가능한 행동으로 바꾼다.
- 기본 제안은 3단계 이내이며 사용자가 펼치기 전에는 전체 세부 목록을 앞세우지 않는다.
- AI 분해 결과는 제안이며 원문 유지, 단계 수정, 분해 취소가 가능하다.
- 시작 화면은 현재 행동, 남은 시간, 다음 행동만 우선 노출한다.

### 전환 개입

15분 전 예고 → 5분 전 마무리 → 종료 시 전환 행동 → 다음 일정 시작.

- 각 개입은 `곧 전환할 이유`와 다음 행동을 함께 제공한다.
- 알림을 놓치거나 닫아도 상태를 완료 처리하지 않는다.
- 사용자는 개입 강도·시점·음성 사용을 일정별 또는 기본 설정에서 조정할 수 있다.

### 실패 후 복구

지연 감지 또는 사용자 신고 → 남은 일정 재계산 → 최대 3개 복구안 → 적용·수정·유지·취소.

- 첫 문장은 실패 평가가 아니라 지금 가능한 다음 행동이어야 한다.
- `연속 기록이 깨졌습니다`, `계획을 실패했습니다` 같은 수치심 유발 문구를 사용하지 않는다.
- 자동 재배치로 삭제·축소·이동되는 항목과 이유를 변경 전에 보여준다.
- 사용자의 명시적 적용 전에는 기존 계획과 알림을 바꾸지 않는다.

### 기기 캘린더에서 일정 가져오기

일정 탭 → 캘린더 연결 설명 → 읽기 권한 허용 → 캘린더/날짜별 일정 확인 → 가져올 일정 선택 → 초안 확인·수정.

- 앱은 기기에 동기화된 Google Calendar, Apple/iCloud Calendar, Android 로컬·계정 캘린더만 읽으며 별도 클라우드 로그인이나 서버 복제를 요구하지 않는다.
- 운영체제 권한 팝업 전에 읽는 기간과 사용 목적, 플랫폼에 필요한 접근 범위, 거부해도 수동 일정 등록이 가능함을 설명한다.
- 캘린더 이름과 공급자를 색상 외 텍스트로 표시하고 전체·Google·Apple/iCloud·기기별로 필터링한다.
- 일정명·날짜·시간·장소를 확인할 수 있으며 종일 일정은 시간이 없음을 명시한다.
- 일정 카드를 눌러도 초안은 바뀌지 않고 `이 일정 가져오기`를 누른 뒤에만 새 일정 초안에 병합한다.
- 권한 거부·차단, 연결 캘린더 없음, 조회 기간 일정 없음, 조회 실패, 앱 복귀 상태에서 가능한 다음 행동을 제공한다.
- 캘린더 원문은 기기에서만 읽고 TimeAgent에 가져오기로 선택한 필드 외에는 서버나 앱 영구 저장소로 복제하지 않는다.

### 실시간 진행

준비 알림 → 현재 단계 → 완료 → 다음 단계 → 도착.

- 상단에 약속 시간, 예상 도착, 여유/지연 문구를 유지한다.
- 현재 단계와 남은 시간을 화면에서 가장 크게 표시한다.
- 잘못 누른 완료를 취소할 수 있고 앱 복귀 시 상태가 유지된다.

### 대중교통 경로와 실시간 도착정보

TimeAgent의 목표는 지도 앱 전체를 복제하는 것이 아니라, 약속에 늦지 않도록 `언제 준비하고 언제 출발해야 하는지`를 신뢰할 수 있는 근거와 함께 알려주는 것이다. 공급자는 다음과 같이 역할을 분리한다.

| 역할 | 기본 공급자 | 제품 책임 |
|---|---|---|
| 지도·마커·경로선·주소/좌표 | NAVER Maps | 앱 안의 위치 맥락과 경로 시각화 |
| 장소 검색·도보·자동차·택시·대중교통 경로 | TMAP | 이동시간·거리·요금·환승·운행시간표 기반 경로 계산 |
| 버스·지하철 실시간 도착 | TAGO 및 지원 지역 공공 API | 사용자가 실제로 선택한 첫 탑승 구간의 도착 예정 정보 보완 |
| 상세 길찾기·공급자 장애 대체 | NAVER 지도·카카오맵 연결 | 사용자가 외부 지도에서 전체 경로를 직접 확인할 수 있는 복구 행동 |

카카오맵 공개 대중교통 API와 ODsay는 기본 공급자로 중복 도입하지 않는다. 카카오맵은 TMAP 장애율·경로 품질·비용을 실제 운영 지표로 비교할 필요가 생기면 서버 adapter 형태의 보조 공급자로 평가한다. ODsay는 공공 실시간 API의 지역별 운영 비용이 자체 유지 비용보다 커지거나 단일 공급자 SLA가 필요할 때 재검토한다.

#### 경로 계산 요구사항

- 일정 생성·수정 시 출발지, 목적지, 약속 날짜·시각을 서버로 보내며, 서버는 예상 출발 시각에 맞는 TMAP 운행시간표를 조회한다.
- UI와 계획 엔진은 공급자 원시 응답 대신 정규화된 경로 계약을 사용한다. 계약에는 공급자, 계산 시각, 총 소요시간, 거리, 요금, 환승 횟수, 도보 구간, 탑승 노선과 정류장 식별정보, 시간표/실시간 여부를 포함한다.
- 일정 역산에는 경로 요약 결과를 우선 사용하고, 경로선·정류장·탑승 안내가 필요한 화면을 열 때만 상세 경로를 요청한다.
- 목적지나 약속 시각이 바뀌면 이전 경로를 폐기한다. 같은 출발지·목적지·시간대의 결과는 서버에서 짧게 캐시하되 계산 시각을 유지한다.
- AI 추천이 다른 이동수단이나 경로를 제시하더라도 사용자가 적용하기 전에는 확정 계획과 알림을 바꾸지 않는다.

#### 실시간 도착 요구사항

- 실시간 API는 전체 후보 경로가 아니라 사용자가 선택한 경로의 첫 버스 또는 지하철 구간에만 호출한다.
- 출발 30분 전부터 실시간 조회를 활성화하고, 화면이 열려 있을 때도 공급자 제한을 지키도록 최소 20초 동안 같은 결과를 재사용한다.
- `실시간`, `시간표 기준`, `최근 저장값`을 텍스트로 구분하고 마지막 확인 시각을 함께 표시한다. 색상만으로 상태를 전달하지 않는다.
- 실시간 도착정보로 출발 시각이나 준비 계획을 바꿀 필요가 생기면 변경 이유와 전후 시각을 보여주고 사용자의 적용을 받는다.
- TAGO가 지원하지 않는 지역이나 지하철 노선은 지역 adapter가 있을 때만 실시간으로 표시한다. 지원하지 않으면 시간표 기반 경로를 유지하고 외부 지도에서 확인하는 버튼을 제공한다.

#### 오류·비용·데이터 기준

- TMAP 또는 공공 API의 timeout, 429, 5xx가 발생해도 일정과 진행 화면은 사라지지 않는다. 마지막 유효 경로 또는 거리 기반 예상값을 출처와 함께 보여주고 `다시 확인`과 외부 지도 연결을 제공한다.
- API 키는 Supabase Edge Function에만 보관하고 앱 번들, 로그, 분석 이벤트에 포함하지 않는다.
- TMAP은 요약 조회를 우선하고 상세 조회와 실시간 polling을 필요한 시점으로 제한한다. 공급자별 성공률, 지연시간, 호출량과 예상 비용은 원문 위치·검색어 없이 집계한다.
- 원시 경로·실시간 응답은 공급자 약관상 필요한 범위를 넘어 영구 저장하지 않는다. 완료 세션의 이동수단은 개인화 학습 데이터로 축적하지 않는다.

#### 수용 기준

- 미래 날짜의 대중교통 약속을 확정하면 현재 시각이 아니라 해당 날짜·예상 출발 시각의 운행 여부를 반영해 준비 시작과 출발 시각을 계산한다.
- 대중교통 결과에는 예상 소요시간, 요금, 환승 횟수, 총 도보시간과 `시간표 기준` 또는 `실시간` 근거가 표시된다.
- 출발 30분 이내이고 선택 경로에 지원되는 정류장 식별정보가 있으면 첫 탑승편의 도착 예정시간과 확인 시각이 표시된다.
- 실시간 정보가 늦어져 기존 출발 계획이 위험해져도 자동으로 계획을 바꾸지 않고, 해결 가능한 다음 행동과 변경안을 먼저 제시한다.
- 실시간 미지원·권한 거부·네트워크 오류·공급자 장애 상태마다 시간표 기준 유지, 재시도, 외부 지도 확인 중 가능한 복구 행동을 제공한다.
- 같은 입력에 대한 중복 조회가 캐시에 의해 억제되고, 화면 polling이 20초보다 자주 공급자를 호출하지 않는 것을 단위 테스트로 검증한다.
- TMAP 응답 정규화, 미래 시각 전달, 목적지 변경 시 이전 결과 폐기, TAGO 성공·미지원·timeout, 마지막 유효값 fallback을 계약 테스트로 검증한다.

### 지연과 플랜 B

시간 더 필요 → 재계산 → 변경 요약 → 적용/유지 → 진행.

- 해결 방법을 지연 사실보다 먼저 보여준다.
- 변경 전후의 출발/도착/준비 시간 차이를 표시한다.
- 최대 3안에 예상 도착, 비용, 걷기, 환승, 정시 여부, 추천 이유를 표시한다.
- AI가 중요한 행동을 임의로 삭제하지 않는다.

## 상태 요구사항

반드시 일정 없음, 준비 전, 준비 시간 경과, 정상 진행, 지연, 정시 불가능, 네트워크 오류, 위치 권한 거부, 알림 권한 거부, 완료 상태를 제공한다.

## 지표

- 첫 일정 생성 완료율과 소요 시간
- 추가 키 입력 없이 음성 확인 한 번으로 등록한 비율
- 작업 분해 제안 후 5분 안에 첫 행동을 시작한 비율
- 홈 진입 후 현재 행동 확인까지 걸린 시간
- 알림에서 준비 시작으로 전환한 비율
- 15분 예고→5분 마무리→종료 전환별 반응률
- 무시한 알림에서 다음 결정을 완료한 비율
- 지연 제안 확인/적용/거절 비율
- 지연 후 10분 안에 복구된 비율과 남은 일정 유지율
- 계획 대비 실제 단계 오차
- 개인화 시간 추천의 수락·수정·거절 비율
- 정시 또는 약속 전 도착률

지표는 지원 효과를 개선하기 위한 제품 신호이며 ADHD 증상, 치료 효과 또는 개인의 성실성을 판정하는 점수로 사용하지 않는다.

## 근거와 해석 경계

- 성인 ADHD 시간 지각 리뷰는 시간 추정·재현·관리의 어려움을 보고한 연구들이 있음을 보여주지만, 연구 수가 적고 일부 연구는 명확한 연관을 찾지 못했다. 제품은 이를 개인차가 큰 지원 필요로 해석하며 보편적 결함으로 규정하지 않는다.
- NICE NG87은 ADHD 진단을 자격을 갖춘 전문가의 종합 평가 영역으로 두고, 환경 조정과 비약물적 지원을 전문 치료 체계 안에서 다룬다. TimeAgent는 환경·행동 지원 도구로만 포지셔닝한다.
- 참고: [성인 ADHD 시간 지각 연구 리뷰](https://pmc.ncbi.nlm.nih.gov/articles/PMC9962130/), [NICE ADHD 권고](https://www.nice.org.uk/guidance/ng87/chapter/recommendations)
