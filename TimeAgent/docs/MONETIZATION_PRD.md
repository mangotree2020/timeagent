# TimeAgent 수익화 PRD

> 상태: Phase 0 개발 기준
>
> 기준일: 2026-07-28
>
> 연결 문서: [비즈니스 모델](BUSINESS_MODEL.md), [제품 정의](PRODUCT.md)

## 1. 목적

TimeAgent Plus 결제를 구현하기 전에 활성 사용자가 어떤 상품과 가격에 관심을 보이는지 검증한다. 사용자가 핵심 가치를 경험한 뒤에만 제안하고, 결제·연락처·일정 원문을 수집하지 않는 로컬 사전 수요 검증을 제공한다.

이번 단계의 성공은 매출이 아니라 다음 질문에 답하는 것이다.

- 일정 실행을 반복한 사용자가 Plus 설명을 자발적으로 확인하는가?
- 월간, 연간, 학생 연간 중 어떤 상품에 관심을 표시하는가?
- 관심 등록 후 철회 비율은 어느 정도인가?
- 수익화 제안이 핵심 일정 완료와 홈 복귀를 방해하지 않는가?

## 2. 대상 사용자와 해결 문제

1차 대상은 주 2회 이상 준비·이동 일정이 있는 직장인·프리랜서다. 2차 대상은 가격에 민감하지만 시험·면접·아르바이트처럼 지각 비용이 큰 대학생이다.

이들은 캘린더에 일정을 저장하는 기능이 아니라 다음 자동화에 비용을 지불할 가능성이 있다.

- 여러 일정의 준비 시작 시각 자동 계산
- 지연 시 반복 재계산과 Plan B
- 실제 준비 시간 기반 개인화
- 캘린더·AI 입력의 반복 작업 감소

## 3. 범위

### 포함

- 누적 일정 완료 3회 기준의 Plus 제안 자격 계산
- 설정 화면의 Plus 상태·진행도·미리보기 진입점
- Plus 설명, 가격 가설, 상품 선택
- 이 기기만의 관심 등록·상품 변경·철회
- 노출, 관심 등록, 상품 변경, 철회 이벤트의 로컬 계측
- 설정의 로컬 수익화 지표 요약과 전체 측정 데이터 초기화 연동
- 사용자가 공유 전 확인할 수 있는 비식별 Phase 0 결과 요약
- 넓은 사용자 유형 선택, 공유 항목 동의, 운영체제 공유창을 통한 명시적 전달
- 로딩·저장·완료·오류 상태와 접근성 문구

### 제외

- 앱스토어 인앱결제, 체험, 구독 entitlement
- 서버 전송, 이메일·전화번호·푸시 토큰 수집
- 무료 사용량 제한 또는 기존 기능 잠금
- Family/B2B2C 관리자 기능
- 긴급 진행·지연·Journey 화면의 결제 제안
- 백그라운드 자동 업로드, 광고 식별자·기기 식별자 생성

## 4. 사용자 흐름

### 흐름 A — 자격 전

1. 사용자가 설정에서 `TimeAgent Plus`를 확인한다.
2. 앱은 `일정 3회 완료 후 Plus 사전등록 가능`과 현재 완료 횟수를 표시한다.
3. 사용자는 상품 설명을 미리 볼 수 있지만 관심 등록 버튼은 비활성이고, 다음 행동은 일정 완료다.

### 흐름 B — 자격 충족 후 관심 등록

1. 누적 `schedule_completed` 이벤트가 3회 이상이면 자격을 충족한다.
2. 사용자가 설정에서 Plus 미리보기를 연다.
3. 월 ₩5,900, 연 ₩49,000, 학생 연 ₩29,000 중 하나를 선택한다.
4. `이 플랜에 관심 있어요`를 누르기 전에는 저장값이 바뀌지 않는다.
5. 누르면 선택 상품과 시각을 이 기기에 저장하고 완료 문구를 표시한다.
6. 결제·자동 갱신·연락처 수집이 발생하지 않음을 명시한다.

### 흐름 C — 변경과 철회

1. 등록 후 다른 상품을 선택하고 적용하면 관심 상품을 변경한다.
2. `관심 등록 철회`를 누르면 확인 패널을 먼저 표시한다.
3. 확인 전에는 상태를 유지하고, 확인 후 로컬 관심 상태를 초기화한다.
4. 철회 후에도 Plus 설명과 기존 앱 기능을 계속 사용할 수 있다.

### 흐름 D — 오류

1. 로컬 저장을 읽지 못하면 기본 미등록 상태와 오류 문구를 표시한다.
2. 저장에 실패하면 기존 상태를 유지하고 `다시 시도` 가능한 버튼을 제공한다.
3. 오류를 성공으로 표시하거나 관심 이벤트를 중복 기록하지 않는다.

### 흐름 E — Phase 0 결과 공유

1. 사용자가 설정에서 `Phase 0 테스트 결과`를 연다.
2. 앱은 일정·위치·음성 원문 없이 완료 일정 수, Plus 노출·관심·철회, 선택 플랜과 기존 MVP 집계값만 보여준다.
3. 사용자는 학생, 직장인·프리랜서, 준비 루틴 변동형, 응답하지 않음 중 하나를 직접 선택한다.
4. 사용자가 화면의 공유 항목을 확인하고 동의하기 전에는 공유 CTA를 비활성화한다.
5. CTA를 누르면 운영체제 공유창을 열며 앱이 수신자를 자동 선택하거나 서버로 전송하지 않는다.
6. 공유창에서 돌아오면 실제 전달 여부를 한 번 더 묻고, 사용자가 `공유 완료 확인`을 누른 경우에만 `pilot_summary_shared` 로컬 이벤트를 기록한다. 취소·오류는 성공으로 기록하지 않는다.

## 5. 상품 표시 계약

| 상품 | 가격 가설 | 핵심 설명 |
|---|---:|---|
| 월간 Plus | 월 ₩5,900 | 부담 없이 월 단위로 사용 |
| 연간 Plus | 연 ₩49,000 | 월 환산 약 ₩4,083, 월간 대비 약 31% 할인 |
| 학생 연간 | 연 ₩29,000 | 학생 인증 도입 전 가격 수요만 검증 |

상품 설명에는 다음 Plus 후보 가치를 표시한다.

- 스마트 계획·지연 재계산·AI 입력 무제한 후보
- 여러 캘린더 자동 동기화 후보
- 실제 준비 시간 기반 개인화와 장기 리포트 후보

아직 제공되지 않는 기능은 `출시 후보`로 표시하며 현재 기능인 것처럼 약속하지 않는다.

## 6. 데이터 계약

### Plus 관심 상태

저장 키: `@on-time/plus-interest`

```ts
type PlusInterestState = {
  version: 1;
  status: 'none' | 'interested';
  plan: 'monthly' | 'annual' | 'student-annual' | null;
  updatedAt: number | null;
};
```

일정명, 장소, 위치, 음성, 사용자 이름, 연락처는 저장하지 않는다. 잘못된 버전·필드·JSON은 기본 상태로 안전하게 되돌린다.

### 분석 이벤트

| 이벤트 | 속성 | 시점 |
|---|---|---|
| `plus_offer_viewed` | eligible, completedSchedules | Plus 화면이 준비된 후 1회 |
| `plus_interest_selected` | plan, previousPlan | 관심 등록 또는 상품 변경 저장 성공 후 |
| `plus_interest_withdrawn` | previousPlan | 철회 저장 성공 후 |
| `pilot_summary_shared` | segment, completedSchedules | 공유창 복귀 후 사용자가 공유 완료를 확인했을 때 |

Plus 화면 재렌더링은 노출 이벤트를 중복 생성하지 않는다. 분석 데이터 초기화는 이벤트만 삭제하며 별도의 관심 상태는 유지한다. 사용자가 관심 상태를 직접 철회할 수 있어야 한다.

## 7. UI·접근성 요구사항

- 본문은 16px을 기본으로 하고 모든 상품 선택과 CTA는 최소 44×44px이다.
- 선택 상품은 테두리·배경색뿐 아니라 라디오 접근성 상태와 `선택됨` 문구로 구분한다.
- 한 화면의 핵심 CTA는 `이 플랜에 관심 있어요` 하나다.
- 뒤로 가기, 관심 철회, 다시 시도는 보조 CTA로 표시한다.
- 저장 결과는 `accessibilityLiveRegion="polite"` 문구로 전달한다.
- 가격과 결제 없음 상태는 화면 읽기 가능한 텍스트로 제공한다.
- 360×800, 390×844, 430×932에서 가로 잘림이 없고 세로 스크롤로 모든 CTA에 접근할 수 있어야 한다.

## 8. 수용 기준

### M0-01 자격 계산

Given 로컬 분석 이벤트에 완료 일정이 0~2개 있음, When Plus 상태를 계산하면, Then 등록 불가와 남은 완료 횟수를 반환한다.

Given 완료 일정이 3개 이상 있음, When Plus 상태를 계산하면, Then 등록 가능을 반환한다.

### M0-02 명시적 관심 등록

Given 자격을 충족하고 상품을 선택함, When 적용 버튼을 누르기 전이면, Then 저장된 관심 상태는 바뀌지 않는다.

Given 적용 버튼을 누름, When 로컬 저장이 성공하면, Then 상품·갱신 시각을 저장하고 완료 상태와 `plus_interest_selected`를 기록한다.

### M0-03 철회

Given 관심 등록 상태임, When 철회 확인 전이면, Then 기존 관심을 유지한다.

Given 철회를 확인함, When 로컬 삭제가 성공하면, Then 기본 상태로 바꾸고 이전 상품과 함께 `plus_interest_withdrawn`을 기록한다.

### M0-04 투명성과 안전

Given Plus 화면을 확인함, Then 실제 결제·자동 갱신·연락처 수집이 없고 출시 후보 기능임을 명확히 표시한다.

Given 진행·지연·이동 화면을 사용 중임, Then Plus 결제 또는 관심 등록 화면을 자동으로 띄우지 않는다.

### M0-05 오류·복구

Given 잘못된 저장값이 있음, When 화면을 열면, Then 앱이 중단되지 않고 미등록 기본 상태로 복구한다.

Given 관심 저장이 실패함, When 결과를 표시하면, Then 성공 이벤트를 기록하지 않고 기존 상태와 다시 시도 행동을 유지한다.

### M0-06 비식별 결과 공유

Given Phase 0 결과 화면을 열었음, When 공유 내용을 확인하면, Then 일정명·장소·위치·음성·연락처·기기 식별자·정확한 이벤트 시각을 포함하지 않고 집계값과 사용자가 선택한 넓은 유형만 표시한다.

Given 사용자 유형 또는 공유 동의가 없음, When 화면을 확인하면, Then 공유 CTA는 비활성이다.

Given 사용자 유형을 선택하고 공유 항목에 동의함, When 공유 CTA를 누르면, Then 운영체제 공유창을 열고 앱은 수신자를 자동 선택하지 않는다.

Given 공유창에서 앱으로 돌아옴, When 실제 전달 여부 확인이 필요하면, Then `공유하지 않았어요`와 `공유 완료 확인` 행동을 제공하고 완료 확인 전에는 성공 이벤트를 기록하지 않는다.

Given 공유를 취소하거나 오류가 발생함, When 결과가 돌아오면, Then 성공 이벤트를 기록하지 않고 다시 시도 행동과 로컬 데이터를 유지한다.

## 9. 성공 지표와 다음 단계 게이트

초기 50~100명 테스트에서 다음을 세그먼트별로 확인한다.

- 자격 사용자 중 Plus 화면 확인률
- Plus 화면 확인자 중 관심 등록률
- 월간/연간/학생 연간 선택 비율
- 관심 등록 후 철회율
- Plus 제안 전후 일정 완료율 변화

인앱결제 개발은 첫 계획 완료율 60% 이상, D7 유지율 25% 이상, 14일 내 스마트 계획 3회 완료율 30% 이상과 함께 활성 사용자 인터뷰에서 반복적인 지불 의사가 확인된 뒤 별도 PRD로 진행한다.

로컬 계측만으로 전체 코호트 전환율을 산출할 수 없으므로 Phase 0 테스트 운영자는 참여자의 설정 지표를 동의하에 집계한다. 서버 분석을 추가하려면 수집 목적·보존 기간·동의 철회·삭제 계약을 먼저 정의한다.
